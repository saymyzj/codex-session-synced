# Codex Synced 1.2.7

English | [中文 ->](https://github.com/saymyzj/codex-session-synced/blob/main/docs/release/v1.2.7.md)

Codex Synced 1.2.7 fixes a Windows installer issue where the app could read a stale SQLite state database when launched outside Codex Desktop. Even without inheriting the `CODEX_SQLITE_HOME` environment variable, the app now prefers `%USERPROFILE%\.codex\sqlite\state_*.sqlite`, preventing `session_index.jsonl` from being rebuilt from an old root database and hiding Codex Desktop sidebar history.

## Fixes

- Windows now prefers the active `Codex Home\sqlite\state_*.sqlite` directory when SQLite Home is not explicitly configured and `CODEX_SQLITE_HOME` is unavailable, instead of falling back to a stale root database.
- macOS Core uses the same SQLite Home discovery rule so both platforms stay aligned.
- Windows scans rollout files, `session_index.jsonl`, and global state files with shared read access, so an active rollout held open by Codex no longer aborts the whole scan.
- Windows self-test now covers both locked rollout scanning and the migrated `sqlite` state directory layout.

## Safety Boundary

This release only fixes local history visibility metadata discovery and scanning. It does not modify OAuth tokens, API keys, third-party API URLs, Provider configuration, or conversation bodies. You should still fully quit Codex before applying repairs so the running app-server cannot write stale in-memory state back to local files.

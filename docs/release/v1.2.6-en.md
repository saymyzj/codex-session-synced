# Codex Synced 1.2.6

English | [中文 ->](https://github.com/saymyzj/codex-session-synced/blob/main/docs/release/v1.2.6.md)

Codex Synced 1.2.6 restores the cross-provider history visibility repair path. After switching to `custom`, `openai_http`, or another third-party provider, the app now defaults to aligning recoverable local conversation history to the active provider so Codex Desktop can show older sidebar conversations again. Users who only want conservative sidebar-summary repair can turn this option off in Settings.

## Fixes

- Restores history visibility after provider switching by aligning unarchived, resume-compatible local threads with existing rollout files to the active provider by default.
- Provider alignment now previews and backs up both SQLite `threads.model_provider` and the rollout first-line `session_meta.payload.model_provider`, preventing SQLite/rollout metadata drift.
- Adds a Settings toggle for "Cross-provider history visibility"; disabling it returns to the conservative 1.2.5 strategy that only repairs Provider rows proven wrong by rollout metadata.
- Adds visible progress bars on macOS and both Windows WPF/WinForms UIs for scan, backup, repair, and restore work, including phase text and percent progress.
- Adds rollout Provider changes to the pending repair preview.
- Extends the Windows self-test to cover both conservative Provider repair and cross-provider alignment.

## Safety

Codex Synced only repairs local sidebar summary and history visibility data. Cross-provider alignment only changes local history metadata Provider fields. It does not modify OAuth tokens, API keys, third-party API URLs, provider configuration, or conversation bodies, and it never uploads local history.

Quit Codex completely before repairing so the running app-server cannot write stale in-memory state back to local files.
